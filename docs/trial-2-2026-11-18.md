# 실전 시험 2회 (2026-11-18)

1회차에서 검증되지 않았던 것 하나만 봤습니다. **기존 방식으로 짠 코드를 린트 에러 메시지만 보고 올바르게 고칠 수 있는가.**

## 요약

- **한 번에 고쳤습니다.** 작은 모델(Haiku) 에이전트가 린트 에러 17건을 모두 없애고 동작 테스트 7개를 통과시켰습니다. 잘못 고쳤다가 되돌린 것은 없었고, 걸린 시간은 약 1분 40초입니다.
- **규칙을 우회하지 않았습니다.** 바뀐 파일은 고치라고 한 파일 하나뿐이고, 테스트와 설정은 그대로입니다.
- **메시지가 부족한 곳을 3가지 찾아 고쳤습니다.** 가장 큰 것은 `useEffect` 금지 메시지에 "서버 데이터를 불러오는 경우"의 안내가 없었던 것입니다.
- **교정 1건**: 검색 조회에 `useData`를 써서 검색할 때 목록이 깜빡였습니다. `check`는 통과하지만 1회차에서 고친 문제와 같은 것입니다.

## 시험 방법

- **주어진 코드**: 공지사항 화면을 기존 방식으로 짠 파일 하나. `useEffect` 4개, `fetch` 2곳, `setTimeout` 2곳, `addEventListener` 2곳, `eslint-disable` 주석, `!` 단언.
- **출발 상태**: 린트 에러 17건, 동작 테스트 7개 중 5개 실패.
- **성공 기준**: `pnpm check` 통과. 테스트는 미리 써 두었고 고칠 수 없게 했습니다.
- **기준 검증**: 프레임워크 API로 정답을 먼저 구현해 테스트 7개가 통과하는 것을 확인한 뒤, 정답을 치우고 기존 방식 코드로 바꿔 넣었습니다.
- **읽기 제한**: 모듈의 규칙 파일, 통과 예제, 프레임워크 테스트, 문서, 샘플 앱의 다른 기능은 읽지 못하게 했습니다. 프레임워크 소스는 타입 확인용으로 허용했습니다.

읽기 제한은 지시일 뿐 기술적으로 막은 것이 아닙니다. 에이전트는 금지된 것을 읽지 않았다고 보고했고, 이는 확인할 수 없습니다.

## 결과

| 항목 | 결과 |
|---|---|
| 바뀐 파일 | `apps/sample/src/notices/NoticeBoard.tsx` 하나 (시험 전 백업과 비교) |
| 린트 에러 | 17건 → 0건 |
| 동작 테스트 | 2개 통과 → 7개 통과 |
| 금지 패턴, 탈출구 | 0건 |
| `pnpm check` | 통과 (직접 다시 실행, 종료 코드 0) |
| 잘못 고쳤다가 되돌린 횟수 | 0 (에이전트 보고) |

에이전트가 고친 결과는 미리 만들어 둔 정답과 구조가 거의 같습니다. 조회는 `defineQuery`와 `useData`, 등록은 `defineMutation`과 `useMutate`, 로딩과 실패는 `DataBoundary`, 디바운스·바깥 클릭·Escape·2초 안내는 Effect 모듈의 훅으로 옮겼습니다. 다른 값에서 계산되는 `count` 상태는 없애고 렌더 중에 계산했습니다.

## 메시지만으로 된 것과 안 된 것

- **메시지만으로 된 것**: 어떤 훅으로 바꿀지 고르는 일. 타이머, 이벤트 리스너, `fetch` 금지 메시지가 대안 이름을 알려 줬습니다.
- **소스를 읽어야 했던 것**: 함수의 인자와 반환값. 에이전트는 프레임워크 소스 10여 개를 읽어 인자 형태를 확인했습니다. 메시지는 "무엇을 쓸지"까지만 알려 주고 "어떻게 쓸지"는 타입에서 읽게 되는 구조입니다.

## 찾은 문제와 조치

| 문제 | 조치 |
|---|---|
| `useEffect` 금지 메시지에 서버 데이터 불러오기에 대한 안내가 없어, 데이터 모듈을 찾는 데 시간이 걸림 | 메시지 첫 줄에 `defineQuery`, `useData`, `DataBoundary` 안내 추가 |
| `fetch` 금지 메시지가 API 클라이언트만 알려 주고 조회·변경 훅은 알려 주지 않음. 그래서 `useDeferredData`를 몰랐고 검색에 `useData`를 씀 | 메시지에 조회(`useData`, `useDeferredData`)와 변경(`useMutate`) 안내 추가 |
| `useClickOutside`가 `mousedown`이 아니라 `pointerdown`에 반응한다는 것이 어디에도 없음 | `addEventListener` 금지 메시지에 추가 |
| `react-hooks/set-state-in-effect`와 `FormEvent` 사용 중단 메시지는 대안을 알려 주지 않음 | 조치 안 함. 외부 플러그인과 React 타입의 메시지라 직접 고칠 수 없음 |

교정 1건(검색 조회의 `useData`)은 `useDeferredData`로 바꿨습니다.

## 한계

- 과제가 정답이 있는 옮기기 작업이었습니다. 프레임워크에 맞는 API가 없는 경우에 메시지가 도움이 되는지는 보지 못했습니다.
- 메시지를 고친 뒤에는 다시 시험하지 않았습니다. 고친 메시지가 실제로 더 나은지는 확인되지 않았습니다.
- 한 번 돌린 결과입니다. 같은 과제를 여러 번 돌려 편차를 보지는 않았습니다.
