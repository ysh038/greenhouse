# 실전 시험 9회: 설치한 패키지로 일하기 (2026-11-25)

프레임워크를 npm 패키지로 만든 뒤, **패키지를 설치한 새 프로젝트에서 에이전트가 문서만 보고 화면을 만들 수 있는지** 봤습니다. 지금까지의 시험에서 에이전트는 이 저장소의 README와 프레임워크 소스를 직접 읽었습니다. 패키지가 되면 그 자리를 패키지 안의 안내 문서(`GUIDE.md`)와 타입 선언이 대신합니다. 이번에 넣고 아직 시험하지 않은 라우터, `Select`, `ProtectedRoute`도 같이 걸렸습니다. 비교 조건은 없고, 프레임워크 쪽만 봤습니다.

## 요약

- **두 에이전트 모두 끝까지 만들었고 `npm run check`가 통과했습니다.** 진행자가 직접 다시 돌려 확인했습니다.
- **기본 사용법은 안내 문서만으로 됐습니다.** 화면 부품, 데이터, 주소 정의, 가짜 서버 연결, 화면 시나리오가 여기에 듭니다.
- **보호된 화면은 문서만으로 안 됐습니다.** 이름만 적혀 있어서 둘 다 타입 선언을 읽었습니다.
- **프레임워크의 빈 곳 둘이 드러났습니다.** 다른 주소로 보내는 수단과 메뉴를 놓을 자리가 없어서 둘 다 우회했습니다. 시험 뒤에 넣었습니다.

## 시험 방법

- 묶은 패키지(`pnpm pack`)로 `init`한 뒤 npm 10으로 설치한 새 프로젝트를 두 벌 만들었습니다(P1, P2). 이 저장소의 파일은 볼 수 없습니다.
- 맥락 없는 Sonnet 에이전트 둘에게 같은 과제를 줬습니다: 로그인, 주문 목록(상태를 고르면 주소에 남음), 주문마다 주소가 있는 상세 화면, 발송 처리 전 확인 창, 관리자만 들어가는 화면. 백엔드는 없고 가짜 서버를 안내만 보고 직접 붙입니다(`tools/compare/packaged/spec.md`).
- 사용법을 어디서 찾았는지(안내 문서, 타입 선언, 소스)를 나눠 보고하게 했습니다.

### 둘 다 헤맨 것

- **`/`에서 주문 목록으로 보내는 수단이 없었습니다.** P1은 타이머로 한 박자 뒤에 옮기는 컴포넌트를 만들었고, P2는 `ProtectedRoute`의 "역할이 맞지 않으면 보내기" 동작을 빌려 썼습니다. 둘 다 스스로 우회라고 적었습니다.
- **메뉴가 본문과 어긋났습니다.** `Page` 바깥에 메뉴를 두니 화면 가장자리에 붙었고, 둘 다 스크린샷 검토에서 이것을 보고 CSS 파일을 만들어 너비를 맞췄습니다.
- **상태를 바꿔도 "불러오는 중"이 뜨지 않았습니다.** 주소가 바뀔 때 이전 목록이 그대로 남습니다. 둘 다 `DataBoundary`에 `key`를 줘서 해결했습니다.
- **`ConfirmDialog`의 역할이 `alertdialog`인 것을 몰랐습니다.** 테스트가 한 번 실패한 뒤 알았습니다.
- **테스트에서 "불러오는 중"을 만드는 법이 문서에 없었습니다.** 타입 선언에서 `hangOnce`를 찾았습니다.

### 스크린샷 검토가 잡은 것

둘 다 모아 보기를 보고 기록하지 않고 고친 곳이 있습니다: 메뉴의 위치(둘 다), 좁게 쪼그라든 상세 카드(P2), 줄마다 밑줄이 그어진 주문 목록(P1).

### 사실이 아니었던 보고

P2는 확인 창이 화면 가운데가 아니라 버튼 근처에 떴다고 적었습니다. 스크린샷을 보니 화면 가운데에 떠 있었습니다.

## 시험 뒤에 고친 것

| 드러난 것 | 조치 |
|---|---|
| 다른 주소로 보내는 수단이 없음 | 라우터 모듈에 `Redirect` 추가 |
| 메뉴를 놓을 자리가 없음 | `Page`에 `header` 추가. 본문과 같은 너비에 놓임 |
| 보호된 화면의 사용 예가 없음 | 안내 문서에 `AccessProvider` 배치, 로그인 화면, 로그아웃의 예 추가 |
| 가짜 서버의 라우트 모양을 모름 | 안내 문서에 `createFakeServer` 예와 `params`, `query`, `body` 설명 추가 |
| 역할 이름을 모름 | 안내 문서에 `dialog`, `alertdialog`, `combobox`, `alert` 명시 |
| "불러오는 중"이 안 뜸 | 안내 문서에 `DataBoundary`의 `key` 설명 추가 |
| 테스트에서 상황 만드는 법 | 안내 문서에 `failOnce`, `hangOnce`, `requests` 설명 추가 |
| 시나리오 파일 하나에 하나, `reload`와 로그인, `expectedConsoleErrors` | 안내 문서에 추가 |

`Page`의 `header`는 설치한 프로젝트에서 스크린샷으로 모양을 확인했습니다. 고친 문서로 에이전트를 다시 시험하지는 않았습니다.

## 한계

- **두 번입니다.** 같은 과제, 같은 모델입니다.
- **비교 조건이 없습니다.** 프레임워크 없이 같은 과제를 시킨 결과와 견주지 않았습니다.
- **동작을 채점 스크립트로 검사하지 않았습니다.** `npm run check` 통과와 에이전트가 쓴 테스트, 스크린샷으로만 확인했습니다. 화면을 직접 눌러 보지 않았습니다.
- **로그인 상태를 두는 곳은 여전히 앱이 만듭니다.** 둘 다 `shared/session.tsx`를 비슷하게 만들었습니다. 프레임워크로 옮길지는 정하지 않았습니다.
- **결과물은 임시 폴더에 있어 남지 않습니다.**
