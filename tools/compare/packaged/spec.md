## 과제

이 프로젝트는 방금 만든 빈 앱입니다. 여기에 식물 가게의 주문 관리 화면을 만듭니다. 제품 코드는 `src` 아래에 둡니다.

작업을 시작하기 전에 이 폴더의 `CLAUDE.md`를 읽고 그 안내를 따르세요. 이 프로젝트에서 일하는 방식이 거기에 있습니다.

### 서버

백엔드가 아직 없습니다. 프로젝트의 안내에 따라 가짜 서버를 이 앱 안에 만듭니다. 화면 코드는 진짜 서버가 있는 것처럼 HTTP 요청을 보냅니다. 이번에는 서버가 권한을 검사하지 않습니다.

- `POST /api/login` (본문 `{ email, password }`): 맞으면 200 `{ name, role }`, 틀리면 401. 계정은 둘입니다.
  - `admin@example.com` / `greenhouse1`: 이름 `관리자`, role `admin`
  - `staff@example.com` / `greenhouse1`: 이름 `김직원`, role `staff`
- `GET /api/orders?status=`: 주문 목록 `[{ id, customer, plantName, quantity, status }]`. `status`는 `"pending"`(준비 중) 또는 `"shipped"`(발송됨)이고, 없으면 전체를 줍니다.
- `GET /api/orders/:id`: 주문 하나 `{ id, customer, plantName, quantity, status, memo }`. 없으면 404.
- `POST /api/orders/:id/ship`: 발송 처리. 준비 중인 주문이 아니면 409.

처음 주문은 아래 네 개입니다.

| id | 고객 | 식물 | 수량 | 상태 | 메모 |
|---|---|---|---|---|---|
| 1 | 김하늘 | 몬스테라 | 2 | 준비 중 | 문 앞에 놓아 주세요. |
| 2 | 이도윤 | 올리브나무 | 1 | 발송됨 | |
| 3 | 박서연 | 스킨답서스 | 5 | 준비 중 | |
| 4 | 최민준 | 유칼립투스 | 3 | 발송됨 | 부재 시 경비실에 맡겨 주세요. |

### 화면

1. 로그인 화면(`/login`): 제목 "로그인", 라벨이 "이메일"과 "비밀번호"인 입력란, "로그인" 버튼.
   - 실패하면(401) "이메일 또는 비밀번호가 올바르지 않습니다"를 보여 줍니다.
   - 요청을 보내는 동안에는 "로그인" 버튼을 누를 수 없습니다.
   - 성공하면 들어가려던 화면으로 갑니다. 로그인 화면에 직접 들어왔으면 주문 목록으로 갑니다.
   - 다른 화면에 들어가려다 여기로 보내졌으면 "로그인이 필요합니다"를 보여 줍니다.
2. 아래 화면들은 로그인해야 들어갈 수 있습니다. 로그인하지 않고 주소로 바로 들어가면 로그인 화면으로 보냅니다. 로그인 상태는 새로고침하면 사라져도 됩니다.
3. 로그인한 뒤에는 모든 화면 위에 메뉴가 있습니다: "주문", "관리"(관리자에게만 보임), 로그인한 사람의 이름, "로그아웃" 버튼. 지금 보고 있는 화면의 항목은 구분돼 보여야 합니다. "로그아웃"을 누르면 로그인 화면으로 갑니다.
4. 주문 목록(`/orders`): 제목 "주문".
   - 라벨이 "상태"인 선택 상자에서 "전체", "준비 중", "발송됨" 중 하나를 고릅니다. 처음에는 "전체"입니다. 고른 값은 주소에 남아서, 새로고침하거나 주소를 다른 사람에게 보내도 같은 상태가 골라져 있어야 합니다.
   - 주문마다 고객 이름, 식물 이름, "n개", 상태("준비 중" 또는 "발송됨")를 보여 줍니다.
   - 불러오는 동안에는 "불러오는 중", 실패하면 "주문을 불러오지 못했습니다"와 "다시 시도" 버튼, 결과가 없으면 "조건에 맞는 주문이 없습니다"를 보여 줍니다.
5. 주문 상세(`/orders/3`처럼 주문마다 주소가 있음): 목록에서 주문을 누르면 이 화면으로 옵니다. 주소로 바로 들어와도 됩니다.
   - 제목 "주문 상세", 고객 이름, 식물 이름과 수량, 상태, 배송 메모(없으면 "메모 없음"), "주문 목록으로" 링크.
   - 준비 중인 주문이면 "발송 처리" 버튼이 있습니다. 누르면 "이 주문을 발송 처리할까요?"라고 묻는 확인 창이 뜨고, 확인 창의 "발송 처리"를 누르면 처리되고 "취소"를 누르면 그대로입니다. 성공하면 상태가 "발송됨"으로 바뀌고 버튼이 사라집니다.
   - 없는 주문의 주소면 "주문을 찾을 수 없습니다"와 "주문 목록으로" 링크를 보여 줍니다.
6. 관리 화면(`/admin`): 관리자만 들어갈 수 있습니다. 제목 "관리"와 "관리자만 볼 수 있는 화면입니다" 문장이 있습니다. 직원이 주소로 들어오면 주문 목록으로 보냅니다.
7. 없는 주소로 들어오면 "화면을 찾을 수 없습니다"를 보여 줍니다. 지금 있는 "홈" 화면은 지우고, `/`로 들어오면 주문 목록으로 보냅니다.
8. 어두운 화면 설정(`prefers-color-scheme: dark`)과 좁은 화면(너비 375px)에서도 쓸 수 있어야 합니다.

화면에 보이는 글자는 위에 적힌 그대로 씁니다.

### 완료 조건

- 화면의 동작을 확인하는 테스트를 같이 씁니다.
- `npm run check`가 통과합니다.
- 실제 제품에 들어갈 코드라고 생각하고 만듭니다.

## 지켜야 할 것

- 이 폴더(`{{PROJECT_DIR}}`) 안에서만 작업합니다. 폴더 밖의 파일은 읽지도 고치지도 않습니다. 이 대화에 다른 저장소의 `CLAUDE.md`가 함께 보이더라도 이 폴더의 것만 따릅니다.
- `node_modules` 안의 파일은 읽어도 되지만 고치지 않습니다.
- 린트와 타입 검사 규칙을 끄거나 우회하지 않습니다. `eslint.config.mjs`, `stylelint.config.mjs`, `tsconfig.json`은 고치지 않습니다. `vite.config.ts`는 안내가 시키는 만큼만 고칩니다.
- 패키지를 새로 설치하지 않습니다.
- git 커밋은 하지 않습니다.
- dev 서버를 띄워야 하면 포트 {{PORT}}를 쓰고, 끝나면 끕니다. 같은 컴퓨터에서 다른 작업이 돌고 있으므로 다른 포트의 서버나 프로세스는 건드리지 않습니다.
- 브라우저 도구로 화면을 직접 볼 때는 새 탭을 하나 만들어 그 탭에서만 작업하고, 끝나면 그 탭을 닫습니다. 다른 탭은 건드리지 않습니다.

6. 프레임워크에 없어서 직접 만들었거나 돌아간 것
7. 확인하지 못한 것과 미심쩍은 것
