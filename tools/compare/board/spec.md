## 과제

이 앱에 로그인 화면과 게시판 관리 화면을 만듭니다. 화면 코드는 `{{SRC}}` 아래에 두고, `{{SRC}}/App.tsx`에 연결합니다. 지금 있는 "온실 관리" 제목과 "여기에 화면을 추가합니다" 문장은 지웁니다.

작업을 시작하기 전에 이 폴더의 `CLAUDE.md`를 읽고 그 안내를 따르세요. 이 프로젝트에서 일하는 방식이 거기에 있습니다.

### 서버

백엔드가 아직 없습니다. 아래 API를 흉내 내는 가짜 서버를 이 앱 안에 직접 만듭니다.

- 화면 코드는 진짜 서버가 있는 것처럼 HTTP 요청을 보내고 응답을 받습니다. 나중에 진짜 서버로 바꿀 때 화면 코드를 고치지 않아도 되어야 합니다.
- 브라우저에서는 모든 응답이 400ms 늦게 옵니다. 테스트에서는 바로 와도 됩니다.
- 데이터는 메모리에만 둡니다. 새로고침하면 게시글이 처음 상태로 돌아가도 됩니다.

API:

- `POST /api/login` (본문 `{ email, password }`): 맞으면 200 `{ token, name }`, 틀리면 401. 계정은 하나입니다: 이메일 `admin@example.com`, 비밀번호 `greenhouse1`, 이름 `관리자`.
- 아래 요청은 모두 `Authorization: Bearer <token>` 헤더가 있어야 하고, 없거나 틀리면 401입니다.
- `GET /api/posts`: 게시글 목록 `[{ id, title, author, createdAt, isHidden }]`. `createdAt`은 ISO 8601 문자열입니다.
- `POST /api/posts` (본문 `{ title }`): 게시글 추가. 작성자는 로그인한 사람의 이름입니다. 제목이 비어 있으면 400.
- `PATCH /api/posts/:id` (본문 `{ isHidden }`): 숨김 여부 변경.
- `DELETE /api/posts/:id`: 삭제.

처음 게시글은 아래 세 개입니다.

| 제목 | 작성자 | 작성일 | 숨김 |
|---|---|---|---|
| 봄맞이 분갈이 안내 | 관리자 | 2026-03-02 | 아니오 |
| 온실 휴무일 공지 | 김하늘 | 2026-03-10 | 아니오 |
| 지난 행사 사진 | 이도윤 | 2026-02-14 | 예 |

### 화면

1. 로그인 화면: 제목 "로그인", 라벨이 "이메일"과 "비밀번호"인 입력란, "로그인" 버튼.
   - 로그인에 실패하면(401) "이메일 또는 비밀번호가 올바르지 않습니다"를 보여 줍니다.
   - 요청을 보내는 동안에는 "로그인" 버튼을 누를 수 없습니다.
   - 성공하면 게시판 관리 화면으로 넘어갑니다.
2. 게시판 관리 화면: 제목 "게시판 관리", "관리자님"처럼 로그인한 사람의 이름, "로그아웃" 버튼.
3. 게시글 목록: 글마다 제목, 작성자, 작성일(`2026-03-02` 모양)을 보여 줍니다. 숨긴 글에는 "숨김"이라고 표시합니다.
   - 불러오는 동안에는 "불러오는 중"
   - 불러오기에 실패하면 "게시글을 불러오지 못했습니다"와 "다시 시도" 버튼
   - 글이 하나도 없으면 "게시글이 없습니다"
4. 글 추가: 라벨이 "제목"인 입력란과 "추가" 버튼. 추가에 성공하면 목록에 그 글이 보이고 입력란이 비워집니다. 제목이 비어 있으면 "제목을 입력해 주세요"를 보여 줍니다.
5. 글마다 "숨기기" 버튼(숨긴 글이면 "보이기")과 "삭제" 버튼이 있습니다. "삭제"를 누르면 "이 게시글을 삭제할까요?"라고 묻는 확인 창이 뜨고, 확인 창의 "삭제"를 누르면 지워지고 "취소"를 누르면 그대로입니다.
6. "로그아웃"을 누르면 로그인 화면으로 돌아갑니다. 로그인한 채로 새로고침하면 로그인이 유지됩니다.
7. 어두운 화면 설정(`prefers-color-scheme: dark`)과 좁은 화면(너비 375px)에서도 쓸 수 있어야 합니다.

주소(URL)는 화면마다 달라지지 않아도 됩니다. 화면에 보이는 글자는 위에 적힌 그대로 씁니다.

### 완료 조건

- 화면의 동작을 확인하는 테스트를 같이 씁니다.
- `pnpm check`가 통과합니다.
- 실제 제품에 들어갈 코드라고 생각하고 만듭니다.

## 지켜야 할 것

- 이 폴더(`{{PROJECT_DIR}}`) 안에서만 작업합니다. 폴더 밖의 파일은 읽지도 고치지도 않습니다. 이 대화에 다른 저장소의 `CLAUDE.md`가 함께 보이더라도 이 폴더의 것만 따릅니다.
- 린트와 타입 검사 규칙을 끄거나 우회하지 않습니다. 설정 파일은 고치지 않습니다.
- git 커밋은 하지 않습니다.
- dev 서버를 띄워야 하면 포트 {{PORT}}를 쓰고, 끝나면 끕니다. 같은 컴퓨터에서 다른 작업이 돌고 있으므로 다른 포트의 서버나 프로세스는 건드리지 않습니다.
- 브라우저 도구로 화면을 직접 볼 때는 새 탭을 하나 만들어 그 탭에서만 작업하고, 끝나면 그 탭을 닫습니다. 다른 탭은 건드리지 않습니다.
