# 비교 시험 재료

프레임워크가 있을 때와 없을 때 에이전트가 만든 결과를 비교하는 시험(실전 시험 5회와 6회)에 쓴 재료입니다. 워크스페이스에 속하지 않고, 저장소의 린트와 테스트 대상도 아닙니다.

| 위치 | 내용 |
|---|---|
| `spec.md` | 두 조건에 똑같이 준 과제 지시문. `{{...}}` 자리에 경로만 바꿔 넣습니다 |
| `baseline/` | 프레임워크 없는 조건의 출발점. 같은 스택의 일반적인 앱입니다 |
| `framework-start/` | 프레임워크 있는 조건의 출발점에서 바꾼 파일들 |
| `accept.mjs` | 채점 스크립트. 구현을 모르는 채로 브라우저에서 화면만 보고 24가지를 검사합니다 |
| `accumulate/` | 화면이 쌓일 때를 비교한 시험(실전 시험 6회)의 재료. [accumulate/README.md](accumulate/README.md)에 설명이 있습니다 |

## 프레임워크 있는 조건의 출발점 만들기

1. 이 저장소를 복사합니다(`node_modules`, `.git`, `evidence`, `tools` 제외).
2. `apps/sample/src`에서 기존 화면 폴더(`users`, `notices`, `todos`, `invites`, `tasks`, `demo`)를 지웁니다.
3. `docs/`의 시험 기록(`trial-*.md`)을 지우고, README에서 시험 기록 링크와 진행 상황을 걷어 냅니다.
4. `framework-start/`의 파일을 `apps/sample/src`의 같은 위치에 덮어씁니다.
5. `pnpm install` 뒤 `pnpm check`가 통과하는지 확인합니다.

## 채점

저장소 루트에서 실행합니다. 설치된 Chrome을 씁니다.

```bash
node tools/compare/accept.mjs <앱 폴더> <결과 폴더> <포트>
```

앱 폴더는 `vite`를 띄울 수 있는 폴더입니다(프레임워크 조건은 `apps/sample`, 기준 조건은 프로젝트 루트). 결과 폴더에 `accept.json`과 스크린샷이 생깁니다.

## 주의

- 채점 항목은 사람이 골랐습니다. 무엇을 넣고 뺐는지가 결과에 영향을 줍니다.
- 처음에는 프레임워크로 만든 기준 구현으로만 스크립트를 검증해서, 모달로 만든 패널을 잘못 채점했습니다. 실패가 나오면 채점 오류가 아닌지 먼저 화면에서 직접 확인합니다.
